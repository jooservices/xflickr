# Internationalisation (web)

English is the default UI language. Users can switch to Vietnamese from the
app shell header (and the auth header). The choice is stored in
`localStorage` under `xf.locale` (wrapped in try/catch). Per-user server
storage is a later phase.

## Stack

- `i18next` + `react-i18next` (exact pinned versions in `web/package.json`)
- Init: `web/src/shared/i18n/init.ts`
- `I18nextProvider` mounts once in `web/src/app/App.tsx`
- Hook: `useI18n()` → `{ locale, setLocale, toggleLocale, t }`
- Language control: `LanguageSwitcher` (used by the shell `LangToggle`)

## Catalogs

Namespaced JSON under `web/src/shared/i18n/locales/{en,vi}/`:

`admin`, `auth`, `common`, `crawl`, `errors`, `keys`, `login`, `profile`,
`setup`, `shell`.

Keys are dotted paths by meaning (`keys.remove.title`), never the English
sentence. Call sites use the full `namespace.key` form:
`t('shell.nav.library')`.

Interpolation uses `{{name}}`. Plurals use i18next suffixes `_one` / `_other`
(and `_zero` when needed). Vietnamese always defines `_other` (and matching
suffixes so en/vi key sets stay identical).

## Adding a string

1. Add the English entry under the right namespace file.
2. Add the Vietnamese translation (formal-neutral “bạn” register).
3. Reference it with `t('namespace.key')` — never hard-code JSX text.
4. Run `npm run lint` (runs `scripts/check-i18n.mjs`).

## Adding a language

1. Copy `locales/en/*.json` to `locales/<code>/`.
2. Translate every value; keep key sets identical.
3. Extend `LOCALES` / resources in `init.ts` and the language switcher.

## Glossary and DATA

`web/src/shared/i18n/glossary.json` lists product terms that must stay
literal in every language (for example `cream pie`, `Green Bee`). Use
`<Term>` for those. Genre names, tags, titles and user names are **DATA**:
render them as-is and never pass them through `t()`. Admin editing of the
glossary is a later phase.

## Server errors

Map stable problem/API `code` values (and `/problems/...` basenames) through
`translateErrorCode` / the `errors` namespace. Unknown codes use
`errors.generic`. Never show a raw server English sentence.

## CI guards

- `web/scripts/check-i18n.mjs` (via `npm run lint`): identical en/vi keys, no
  empty values, no unused keys, every referenced key exists.
- ESLint `i18next/no-literal-string` in JSX markup mode (tests and glossary
  terms exempt).
