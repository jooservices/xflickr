# XFlickr internationalisation and copy deck rules

English (`en`) is the source of truth. Vietnamese (`vi`) is the only other
language. Language is chosen in the top bar (EN/VI toggle) and Profile, stored
per user, and written to `<html lang>`. See [`patterns.md`](patterns.md) for
default copy and [`design-system.md`](design-system.md) for text expansion.

## Key naming

- Format: `area.view.element`, lowercase, dot separated, words inside a segment
  joined with a hyphen. Examples: `user.library.empty.title`,
  `admin.nodes.add-button`, `shell.live.paused`.
- Areas: `shell` (top bar, rail, toasts, offline), `auth`, `user`, `admin`,
  `common` (buttons and states used everywhere), `error` (messages by code).
- Elements for states: `.title`, `.text`, `.cta` under `empty`, `error`, and
  `loading`. Example: `user.contacts.empty.cta`.
- Keys name the place and role, never the English text. Do not use the English
  sentence as a key (the POC does; the product does not).
- A key is never reused for two meanings. Shared words (Save, Cancel, Retry)
  live in `common.*`.
- Interpolation uses named placeholders: `{count}`, `{name}`, `{date}`. Never
  concatenate translated fragments.
- Keys are never built dynamically from data except for enums with a fixed
  prefix (`common.status.<state>`), and each value is listed in the catalog.
- Catalog files: `web/src/i18n/en.json` and `vi.json`, flat objects keyed by
  the full dotted key. A check fails the build when `vi` has a key `en` lacks,
  and warns when `en` has a key `vi` lacks.

## English source rules

- Sentence case for titles, buttons, and labels ("Add key", not "Add Key").
- Buttons start with a verb. Titles of empty states say what is missing.
- No exclamation marks, no jargon without explanation, no humour in errors.
- Plain words: "key" for a Flickr API key, "contact" for a Flickr contact,
  "node" for a cluster node. Do not mix synonyms.
- Do not mention WireGuard or foreign regions as product concepts.
- Error text: what failed, why if known, what to do next.
- Every string is written to expand 30% (see design-system) and has context in
  the catalog `_comment` field when it is ambiguous.

## Vietnamese translation rules

- Use the formal-neutral "bạn" register. No slang, no emoji.
- Keep established product nouns as Vietnamese terms where users know them:
  Ảnh, Album, Thư viện, Liên hệ, Khóa & hạn mức, Tải xuống, Thông báo,
  Chia sẻ, Hồ sơ. POC VI table is the starting glossary.
- Keep untranslated: Flickr, XFlickr, Google Photos, Drive, OneDrive, Dropbox,
  S3, API, ZIP, SSE, node names, IDs, and code values.
- `Live` is "Trực tiếp", `Paused` is "Tạm dừng", `Retry` is "Thử lại",
  `Cancel` is "Hủy", `Save` is "Lưu".
- Sentence case as in English. Keep full diacritics (UTF-8, NFC). Never strip
  tones.
- Do not translate word for word; keep the meaning and the action verb first.
- Vietnamese has no plural inflection and no grammatical gender for these
  strings, but some words need classifiers ("3 ảnh", "5 liên hệ").
- A missing Vietnamese string falls back to English at runtime and is logged.
  Release checks require 100% coverage for user-facing views.
- Names, titles, and tags from Flickr are shown as they are and never
  translated.
- The glossary is extended in `web/src/i18n/glossary.md` when a term is added.

## Number, date, and duration formatting

Use `Intl` with the active locale (`en-US` or `vi-VN`). Never hand format.

| Value | Rule | en-US | vi-VN |
| --- | --- | --- | --- |
| Integer | `Intl.NumberFormat` grouping | 1,284,330 | 1.284.330 |
| Decimal | One fraction digit for rates and percentages | 96.2% | 96,2% |
| Percent | Whole number unless below 10% | 41% | 41% |
| Bytes | Binary units KB, MB, GB, one decimal | 18.4 GB | 18,4 GB |
| Currency | Not used | — | — |
| Date | `dateStyle: medium` | Oct 25, 2026 | 25 thg 10, 2026 |
| Time | 24-hour `HH:mm` (seconds in logs) | 14:05 | 14:05 |
| Date and time | Date, then time | Oct 25, 2026, 14:05 | 14:05 25 thg 10, 2026 |
| Relative | `Intl.RelativeTimeFormat`, under 1 minute "just now", under 24 h hours, then date | 3 minutes ago | 3 phút trước |
| Duration | Two largest units, short: `1h 20m`, `45s`; under 1 s `850 ms`; never more than two units | 1h 20m | 1 giờ 20 phút |
| ETA | "about" plus duration | about 12m | khoảng 12 phút |

- Time zone: show times in the user's time zone from the browser. Logs and
  audit rows show UTC with a `UTC` suffix when the viewer is an admin and the
  setting "Show times in UTC" is on.
- Store and send ISO 8601 UTC in the API. Format only at the edge of the UI.
- Machine values (IDs, NSIDs, hashes, ports) are never formatted or translated,
  and use the mono family.
- Numeric columns use tabular numerals and align right.

## Pluralisation

- Use `Intl.PluralRules` with ICU message syntax in the catalog:
  `{count, plural, one {# photo} other {# photos}}`.
- English needs `one` and `other`. Vietnamese needs only `other`, but the key
  must still define `other`. Always include `other`.
- Zero is a separate message when it changes the meaning: use `=0 {No photos}`
  instead of "0 photos" in empty states and summaries.
- The count is formatted with the number rule above.
- Never build plurals with "(s)" or by appending "s".
- Ordinals are not used. Counts in sentences follow the same message format as
  counts in labels.
