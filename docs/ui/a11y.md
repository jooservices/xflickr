# XFlickr accessibility rules

Target: WCAG 2.2 level AA on every screen, both roles, all four themes. Colour
contrast values are recorded in [`design-system.md`](design-system.md). Shared
behaviour is in [`patterns.md`](patterns.md).

## WCAG 2.2 AA checklist per component type

Each row lists what must be true before a component is accepted.

| Component | Checklist |
| --- | --- |
| Text and headings | One `h1` per view, no skipped levels. Contrast ≥ 4.5:1 (3:1 for text ≥ 24px or ≥ 19px bold). Text resizes to 200% and reflows at 320 CSS px without loss. Line spacing overrides do not clip. Language set on `<html lang>` and on inline foreign text. |
| Buttons | Native `<button>`. Visible text or `aria-label`. Name matches visible label. Target ≥ 40px (≥ 24px is the WCAG minimum, 2.5.8). Disabled state keeps contrast of text ≥ 3:1 where it conveys state and has a reason in a title or nearby text. |
| Icon buttons | `aria-label` in the current language. Icon is `aria-hidden`. Tooltip text equals the label and also appears on keyboard focus. |
| Links | Distinguishable from text without colour alone. Describe the destination. Opening a new tab is announced. |
| Form fields | Visible `<label for>`. Help and error text linked with `aria-describedby`. Required marked with text. Errors identify the field and the fix, use text plus icon, and move focus to the first invalid field on submit. `autocomplete` on identity fields. Never rely on placeholder as label. |
| Selects, chips, switches | Native `select` or `role="switch"` with `aria-checked`; filter chips use `aria-pressed`. Group has a label (`role="group"`). State is not colour only. |
| Tabs | `role="tablist"`, `tab`, `tabpanel`, `aria-selected`, `aria-controls`. Arrow keys move between tabs, Tab enters the panel. |
| Tables | `<table>` with `th scope`. Caption or `aria-label`. Sortable headers are buttons with `aria-sort`. Narrow layouts keep header association. Live tables do not move focus. |
| Lists and cards | Clickable card has one primary control (a link or button), not a clickable `div` with nested controls. If `role="button"` is used (POC grid tiles), `tabindex="0"` and Enter and Space activate it. |
| Progress and charts | Progress bar has `role="progressbar"` with `aria-valuenow`, or an `img` role with a text value. Every chart has a text summary and a data table or list alternative. Series differ by shape or label, not only by colour. Graphic contrast ≥ 3:1. |
| Status pills and badges | Text states the status; colour is secondary. Contrast ≥ 4.5:1. |
| Toasts and banners | See screen reader announcements below. Do not hold information that disappears before it can be read. |
| Modals | See focus management. `role="dialog"`, `aria-modal="true"`, labelled by its heading. |
| Drawers and rails | Off-canvas drawers behave as modals. A permanent rail is a `nav` landmark with `aria-current="page"` on the active link. |
| Lightbox | `role="dialog"` with `aria-label` of the photo title. Image `alt` is the title or caption. Prev and next buttons labelled. |
| Images | Meaningful photos have concise `alt`. Decorative art uses `alt=""`. Placeholders are not announced as photos. |
| Motion | Honours `prefers-reduced-motion`. No flashing above 3 per second. Auto-updating content can be paused (the Live toggle). |
| Drag, hover, gestures | A single-pointer alternative exists for every drag or swipe (2.5.7). Hover content is dismissible, hoverable, and persistent (1.4.13). |
| Focus | Visible 2px accent outline with 2px offset on every focusable element, never removed. Focus is not hidden behind sticky bars (2.4.11): use `scroll-padding` for the top bar. |
| Authentication | No cognitive test. Password fields allow paste and password managers (3.3.8). |
| Consistent help | Help and navigation sit in the same place on every view (3.2.6). |
| Redundant entry | Do not ask for the same data twice in one flow (3.3.7). |

## Focus management

General rules:

- Opening an overlay moves focus into it; closing returns focus to the control
  that opened it. If that control no longer exists, focus goes to the view
  `h1` (tabindex `-1`).
- Focus is trapped inside modal overlays (modal, drawer, off-canvas rail,
  lightbox). The page behind is `inert` and the scrim is not focusable.
- `Esc` closes the topmost overlay only. Scrim click closes drawers and the
  rail, but not a modal with unsaved input (it asks first).
- Route change: move focus to the main `h1` and update `document.title` to
  "<view> · XFlickr". A skip link "Skip to content" is the first focusable
  element.

| Overlay | Initial focus | Close returns to |
| --- | --- | --- |
| Modal | Heading, or the first field for a form; the safe action (Cancel) for a destructive confirmation. | Opener. |
| Drawer | Drawer heading. | Opener (table row or button). |
| Notifications drawer | Close button. | Bell button. |
| Off-canvas rail | First nav link. | Menu button. |
| Lightbox | Close button. Arrow keys work while focus is inside. | The photo tile that opened it, which keeps its place in the list. |
| Session-expiry modal | `Sign in` button. Cannot be dismissed with `Esc`. | Not applicable; sign-in navigates away. |

## Keyboard map

| Keys | Action |
| --- | --- |
| Tab, Shift+Tab | Move focus in DOM order. No positive `tabindex`. |
| Enter, Space | Activate a button or `role="button"` element. Space toggles switches and chips. |
| Esc | Close the topmost modal, drawer, lightbox, rail, menu, or tooltip. |
| ← → | Lightbox previous and next. Move between tabs. |
| ↑ ↓ | Move in menus, listboxes, and radio groups. |
| Home, End | First and last tab, option, or row in a list control. |
| `/` | Focus the search box (USER) when focus is not in a text field. |
| `g` then `h` | Go to the role home view. |
| `?` | Open the keyboard help dialog listing this map. |
| `l` | Toggle Live and Paused when focus is not in a text field. |

Single-character shortcuts are disabled while a text field has focus, and
can be turned off in Profile (2.1.4). Shortcuts never override browser or
screen reader keys.

## Reduced motion

- `prefers-reduced-motion: reduce` sets transitions and animations to `none`
  (POC rule, design-system motion section), including skeleton shimmer, spinner,
  progress, `fresh`, toast entrance, and off-canvas slide.
- The end state is shown at once. Information is never carried by motion alone:
  a spinner has the text "Loading…"; a fresh row has the "N new" count.
- Auto-scrolling and smooth scrolling are off under reduced motion.
- Parallax, autoplay slideshows, and animated charts are not used.

## Screen reader announcements for live regions

- One polite region in the shell (`aria-live="polite"`, `aria-atomic="true"`)
  receives toasts and Live state changes. One assertive region (`role="alert"`)
  receives errors that block work and the session-expiry notice.
- Never put `aria-live` on a fast-changing list or table. For live lists, send
  a throttled summary to the polite region: at most one message every 10 s,
  such as "3 new events". Individual rows are not announced.
- Loading: the status line "Loading <view>…" has `role="status"`; when data
  arrives, announce "<view> loaded" once and set `aria-busy="false"`.
- Empty results after a filter or search announce "No results" with the count.
  Non-empty results announce "<n> results".
- Progress is announced at 25% steps and at completion, not every tick.
- Live state change: "Live data paused", "Live data resumed", "You are
  offline", "Back online".
- Announcements are written with i18n keys and follow the current language.
- Test with NVDA on Firefox, VoiceOver on Safari (macOS and iOS), and
  TalkBack on Chrome. Run axe in E2E with no serious or critical violations.
